# Architecture : où est quoi

Le dépôt est celui de pokefirered ; seuls les éléments modifiés pour Topaze sont listés.

## Données
| Sujet | Fichier |
|---|---|
| Stats, **types**, talents des 151 | `src/data/pokemon/species_info.h` (`.types = {A, B}`) |
| Attaques (type, puissance, effet) | `src/data/battle_moves.h` |
| Apprentissage par niveau | `src/data/pokemon/level_up_learnsets.h` (`LEVEL_UP_MOVE(lvl, move)`, 20 max par Pokémon) |
| Dresseurs (classe, nom) | `src/data/trainers.h` |
| Équipes des dresseurs | `src/data/trainer_parties.h` |
| Rencontres sauvages | `src/data/wild_encounters.json` (régénère un `.h` au build) |
| Cartes, scripts, dialogues | `data/maps/<Carte>/{map.json,scripts.inc,text.inc}` |
| Noms de lieux | `src/data/region_map/region_map_entry_strings.h` |

### Franges de haut d'arbre (docs/topaze/tufts.py)

Un arbre sans pied au-dessus avait donc un haut tronque. `tufts.py ROUTE1|VIRIDIAN` pose au-dessus de chaque haut d'arbre isole un metatile "sol + touffes" (nouveaux metatiles primaires 521-524 dans general_gradient ET general_opal, secondaires ajoutes dans gradient_road / rustboro_opal). Route1 : lignes 4-5 et 39-40 = vraies rangees d'arbres (plus de buissons).

> **RÈGLE ARBRES (à appliquer à toute nouvelle carte)** : un arbre = 2x2 metatiles (haut 1d4/1d5, pied 1dc/1dd). Le pied porte les touffes du haut de l'arbre suivant. Donc : (1) jamais de pied sans haut ni de haut sans pied ; (2) un haut d'arbre dont la case au-dessus n'est pas un pied doit recevoir une frange : lancer `python3 docs/topaze/tufts.py <ROUTE1|VIRIDIAN|PALLET>` (ajouter la carte dans CFG) ; (3) bordures de carte : respecter la parite haut/pied sur toute la colonne, y compris a travers les connexions ; (4) ne pas remplir une ligne vide par des buissons : mettre des arbres ; (5) metatiles primaires ajoutes : memes indices dans tous les tilesets primaires vus a travers une connexion (523/524 = sol+touffes rouges dans gradient, opal, emerald).
